# 美食探店剪辑

横屏探店成片。参考实现是喜鼎探店 v5：`E:/future/photo-asset-manager/src/photo_asset/xiding.py`。新店按同样规则另做一套草稿，不要改喜鼎成片来凑。

剪映草稿的发布和导出容易把工程写坏，步骤见 [jianying.md](jianying.md)。参考片的 Hypit 记录在 `E:/future/hypit-study`，三条已读完的片子见 [references.md](references.md)。

## 成片规格

- 横屏 1920×1080，30fps。口播留在时间线上，底部字幕是短句。
- 原片只读。降噪人声、索引、草稿都写到成片目录，不回写拍摄文件夹。
- 一条故事剪到说完的那句。点评、品尝、排名都留完整。不重要的重复、店员复述、闲聊删掉。不为了卡时长把故事掐断。
- 食材介绍放在菜的右侧，不放进底部字幕轨道。
- 不用剪映会员素材。人声已经降噪，不要加「清澈人声」。导出若变成「开通会员并导出」，去掉会员素材后重发草稿，不要绕过会员校验。

## 流程

```
- [ ] 用户给了参考链接：先用 Hypit 写入 ANALYSIS.md 和 TIMELINE.md，再改剪法
- [ ] 索引画面，再转写口播（两步不要同时占 GPU）
- [ ] 先给出剪辑表：镜号、原片、in-out、这句留什么、落在六拍的哪一拍
- [ ] 食材卡先核对事实，确认后再写入
- [ ] 生成降噪人声、故事板、manifest
- [ ] 剪映关闭后发布新草稿，并改成同一套新 id
- [ ] 打开工程，确认导出按钮不是开通会员，再导出
- [ ] 用 ffmpeg 核对时长和音轨，交成片路径和抖音文案
```

### 1. 索引和口播

机器是 RTX 2060 6GB。不要跑 Video-LLaVA。Chinese CLIP 和 FunASR / SenseVoice 不要同时占 GPU：先做完索引并释放显存，再转写。

- 用 ffmpeg 每 2 秒抽一帧，长边 480。
- CLIP 只用来认空镜、菜、环境，不代替人听口播。
- 口播以转写为准。字幕写人话短句，不把整段 ASR 贴上去。

ffmpeg：`E:/memory/tools/ffmpeg/bin/ffmpeg.exe`。

### 2. 剪辑表

故事按六拍走。菜序填在第三拍里，中间可以跳，因果不能断。

1. 爆点前置。先给最有信息的画面或第一句判断。隋坡开场是满桌菜，人还没出镜。峰哥第一句就是到了，地点在人后面，不做单独片头。
2. 交代目的。今天为什么来、吃什么。
3. 展开叙事。进门或钩子之后：空间 → 菜单和点单 → 茶水、赠菜 → 桌上的主菜 → 品尝和评价 → 价格或一个完整的趣味段落 → 配菜。
4. 穿插意外。留一个和预期相反的判断，说完再走。峰哥在夜市说「乏善可陈」。
5. 结尾高潮。总排名或一笔账，点明还想再点的那道。
6. 涩话开启。收在一句不拿腔的实话上，不收成口号。这六个字来自结构卡最后一列的低码率读法，原片若是别的字，以原片为准。

口播负责判断，空镜负责证明。说「像广东汤粉店」时，画面就是那家店。底部字幕跟嘴：句子用短句，判断可以只留两三个字，例如「现煮」。不要把整段转写贴上去。食材卡仍在右侧，不进底部字幕。

同一章里用叠化 0.28 秒，换章用叠化 0.5 秒。章与章之间留一点空镜，空镜保留现场声。口播镜头把原片音量压低，改听降噪人声。

先把剪辑表给用户看。用户说可以加，再写食材卡和草稿。

### 3. 声音

口播 wav：48 kHz 单声道，滤镜 `highpass=f=90,lowpass=f=8500,afftdn=nr=12:nf=-22:tn=1`。原片不动。

| 轨 | 音量 |
|---|---|
| 口播镜头的原片声 | 0.05 |
| 降噪人声 | 1.0 |
| 空镜原片声 | 0.42 |
| 配乐 | 0.1，淡入 1.6 秒，淡出 2.8 秒 |

人声轨不要加场景特效，也不要打音量关键帧。配乐选吃饭时能垫着的轻音乐，不要预告片或强节奏。短文件可以循环，循环时丢掉末尾 1.2 秒，避免截断文件发出咔嗒声。

若用 Kevin MacLeod《Bossa Antigua》，成片说明里写：Bossa Antigua by Kevin MacLeod, CC BY 3.0, incompetech.com。不要重新下载卡住的完整版，现有片段循环即可。

### 4. 食材卡

每道出现在品尝或介绍那一句上，不挂在一两秒的空镜上。默认停 8 秒；镜头更短就收到镜头内。同一轨道两张卡至少隔 0.15 秒，短于 1.8 秒的卡去掉。

三行，各占一条文字轨（一条轨不能重叠）：

| 行 | 字体 | 字号 | 入场 | 纵坐标 |
|---|---|---|---|---|
| 菜名 | 思源粗宋 | 8 | 向左滑动 0.45 秒 | 0.36 |
| 产地或来历 | 思源中宋 | 5 | 打字机_I 1.1 秒 | 0.14 |
| 做法或吃法 | 思源中宋 | 5 | 向左露出 0.6 秒 | -0.08 |

三行一起出场，消失时都用「向右滑动」0.45 秒。右对齐，`max_line_width` 0.30，`transform_x` 0.50。描边宽度约 8，颜色按 0–1 写，不要写成 0–255。菜不在画面中间时，只改这张卡的 y，不要改整列的 x。字用免费的思源宋，不用会员字体。

写之前先查这道菜的物种、产地、名字来历。写得进画面，一句一行。

- 写食客能核对的事实：物种、产地、名字怎么来的、为什么这样配。
- 不要把家常菜谱写成这家店的做法。
- 不要写和物种矛盾的话（例如浅水蟹写成深海）。
- 卡片跟着品尝的话走。话太长就剪闲聊，不要把卡缩成一闪而过。

例：`东港飞蟹 / 东港冷水梭子蟹，秋后最肥 / 壳肉和腿肉一起炒进蛋里`。蟹和蛋一起出现时，写蛋为什么不压过蟹，不要另做一张蛋的介绍。

### 5. 时间线

轨道顺序：主画面、主标题、副标题、底部字幕、食材、食材注、食材法、人声、配乐。

片头两行分开，不要叠在同一条文字轨上：店名（城市商圈 · 店名，思源粗宋，字号 11，向左滑动），下面一行「探店」（字号 7）。不要用弹入。

底部字幕：思源中宋，字号 6，描边 8，`transform_y` -0.7，跟着该镜头走。

草稿名用店名加版本，例如 `喜鼎探店v5`。用户说在这一版上改，就替换这一版，不要另起一个名字。

### 6. 发布、导出、文案

按 [jianying.md](jianying.md) 发布和导出。导出后用 ffmpeg 看时长、1920×1080、有音轨，再把真实路径告诉用户。

抖音文案跟成片一起给：

- 标题一句具体结论，不要「好吃推荐」。
- 正文按到店顺序，每道菜一句判断，点明还想再点的那道。
- 结尾一个二选一的问题。
- 话题一行、空格分隔，含城市、商圈、店名、主菜、`#美食探店`。不要用反引号包话题。
